# Задание 2

DAG anton_mishin_citybikes_dm строит витрину из таблиц PostgreSQL
и сохраняет её в HDFS. Обработка находится в build_mart.py,
файл DAG - dags/citybikes_to_hdfs.py.

Перед запуском выполнить задание 1 и дождаться статуса success.
Здесь используются уже загруженные сети и станции.

Запуск из корня проекта:

```powershell
docker compose exec airflow-scheduler airflow dags unpause anton_mishin_citybikes_dm
docker compose exec airflow-scheduler airflow dags trigger anton_mishin_citybikes_dm
```

Также DAG можно включить и запустить через http://localhost:8080,
логин и пароль airflow. Дождаться статуса success.
Логи обработки доступны у задачи create_mart.

Результат находится в каталоге /anton_mishin/dm в HDFS:

```powershell
docker compose exec namenode hdfs dfs -ls /anton_mishin/dm
```

Для приложенной выгрузки получается 4 153 строки и 26 полей.
Количество строк записывается в лог. В каталоге находятся файлы .json
и отметка _SUCCESS. Формат - JSON Lines, одна станция на строку.
Посмотреть HDFS можно через http://localhost:9870.

Таблицы объединяются по ID сети через inner join: в витрине нужны станции
вместе с данными их сетей. location, company и extra разбираются через
from_json с явно заданными типами. Повреждённый JSON прерывает обработку.

Числа, массивы и булевы значения записываются в JSON без превращения в строки.
Пропуски сохраняются; 0/1 и true/false приводятся к boolean.
Пробелы по краям удаляются у строк и элементов массивов.
К 24 полям из задания добавляются companies_count с количеством компаний
и network_station с названием сети и станции через /.

Даты в JSON записаны строками вида 2025-04-15 10:00:00, с точностью до секунды.
station_timestamp приводится к UTC. Для station_last_updated без часового пояса
сохраняются исходные часы и минуты. Unix-время и даты с известным смещением
переводятся в UTC. При загрузке в ClickHouse типы дат задаёт его схема.

При повторном запуске витрина заменяется целиком. Сначала Spark пишет
в каталог dm.staging, затем готовый результат переносится в dm.
До завершения замены прежняя копия хранится в dm.previous.
Ошибка записи не удаляет прежнюю витрину; прерванная замена восстанавливается
при повторном запуске. Общий DAG и отдельные этапы следует запускать по очереди.

После success можно выполнять задание 3. Окружение и версии компонентов
описаны в [главном README](../README.md).
